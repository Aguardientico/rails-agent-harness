Código abierto · MIT · Rails 8.1

Barandas para los agentes de IA que programan en tu app Rails.

rails_agent_harness le da a Claude Code, Codex y Cursor las mismas instrucciones, chequeos y protecciones, para que sus cambios pasen por RuboCop, Brakeman y tus tests, y las migraciones salgan del generador, antes de que el agente diga “listo”.

Obtén la gema en GitHub Que te lo configuren 
# En tu app Rails
$ bundle add rails_agent_harness --group development
$ bin/rails g agent_harness:install
      create  config/agent_harness.yml
      create  AGENTS.md
      create  CLAUDE.md
      create  bin/agent-check
      create  .claude/settings.json
      create  .claude/skills/rails-review/SKILL.md

Antes de la primera versión en RubyGems, instálala desde GitHub: gem "rails_agent_harness", github: "Aguardientico/rails-agent-harness", group: :development

Los agentes son rápidos. En una app Rails repiten los mismos errores.

Migraciones escritas a mano

Sin timestamp, con el nombre de clase equivocado y con ediciones directas a db/schema.rb, así que el esquema se desfasa de la base de datos.

Código Rails riesgoso

Consultas N+1, params sin filtrar, SQL con interpolación de strings y efectos secundarios en callbacks.

“Listo” sin verificar

La tarea se da por terminada sin correr el linter, el escáner de seguridad ni los tests.

Cómo funciona

  1. Instala y genera

    Agrega la gema y corre bin/rails g agent_harness:install. El generador detecta tu stack (versión de Rails, RSpec o Minitest, base de datos, RuboCop/Standard, Brakeman, schema.rb o structure.sql) y escribe los archivos de arriba. Haz commit de ellos para que cada desarrollador y cada agente tenga la misma configuración.

  2. El agente corre un solo comando

    bin/agent-check revisa los archivos que cambiaron desde el merge base con tu rama base, sin levantar Rails. Esta es la salida para un cambio descuidado de la demo grabada (en inglés): 

$ bin/agent-check
agent-check: FAIL (migrations, rubocop, brakeman) - 5 files checked in Xs
[migrations] FAIL 1 problem
  db/migrate/add_published_to_posts.rb: does not look generated by bin/rails g migration (expected YYYYMMDDHHMMSS_snake_name.rb)
[rubocop] FAIL 1 offense
  app/models/post.rb:9:5: C: [Correctable] Style/StringLiterals: Prefer double-quoted strings unless you need single quotes to avoid extra backslashes for escaping.
[brakeman] FAIL 1 warning
  app/controllers/posts_controller.rb:5 [High] SQL Injection: Possible SQL injection
[tests] SKIP disabled in config/agent_harness.yml
Fix the issues above, then run bin/agent-check again.
(exit 1)

# Después de generar la migración, parametrizar la consulta y corregir el problema de estilo:
$ bin/agent-check
agent-check: PASS (migrations, rubocop, brakeman, tests skipped: disabled in config/agent_harness.yml) - 5 files checked in Xs

  1. Claude Code se detiene antes de equivocarse

    Los hooks en .claude/settings.json bloquean una migración escrita a mano o una edición del esquema antes de que ocurra, pasan el linter por cada archivo editado y corren el chequeo completo antes de que Claude termine. Codex y Cursor leen AGENTS.md, que les indica correr bin/agent-check y corregir todo lo que reporte.

Qué obtienes

AGENTS.md + CLAUDE.md

Comandos y convenciones para el stack de tu app, dentro de marcadores BEGIN/END. CLAUDE.md importa AGENTS.md. Volver a correr el generador solo actualiza el bloque marcado y conserva tu propio texto.

bin/agent-check

Un solo comando rápido para el conjunto de cambios: reglas de migraciones y esquema, RuboCop (o Standard) sobre los archivos modificados, Brakeman y los tests asociados a los archivos modificados (RSpec o Minitest). Salida en texto plano, una sola línea cuando todo pasa.

Hooks de Claude Code

  • PreToolUse: bloquea migraciones escritas a mano y ediciones del esquema
  • PostToolUse: RuboCop sobre el archivo editado, con los problemas devueltos al agente
  • Stop: el chequeo completo antes de que Claude termine

Guardián de migraciones y esquema

Las migraciones deben salir de bin/rails g migration y el esquema solo cambia mediante db:migrate. Detecta migraciones mal nombradas, una migración sin cambio en el esquema y un cambio en el esquema sin migración.

Skill rails-review

Pídele a Claude que “revise mis cambios” o corre /rails-review: consultas N+1, índices faltantes, strong parameters, callbacks, transacciones, seguridad y tests. La misma lista de revisión vive en AGENTS.md para los demás agentes.

Configurable y seguro de volver a correr

config/agent_harness.yml define la rama base, los límites de salida, el comando de cada chequeo y las protecciones. Las herramientas que no usas se omiten. Los hooks y ajustes existentes se conservan.

Compatibilidad: Ruby 3.3, 3.4 y 4.0 · Rails 8.1 (probado en CI), Rails main como job edge · RSpec o Minitest · RuboCop/Standard y Brakeman opcionales. Documentación completa en el README (en inglés).

Preguntas frecuentes

¿La gema es gratuita?

Sí. La gema principal tiene licencia MIT y la seguirá teniendo. Más adelante podrían llegar paquetes adicionales pagos.

¿Qué agentes soporta?

Claude Code lee CLAUDE.md (que importa AGENTS.md) y recibe los hooks y la skill rails-review. Codex y Cursor leen AGENTS.md. El generador solo instala hooks para Claude Code; para los demás, el chequeo migrations de bin/agent-check detecta las migraciones escritas a mano después de que ocurren.

¿bin/agent-check levanta Rails o corre toda la suite?

No. Nunca levanta Rails y revisa los archivos que cambiaron desde el merge base con tu rama base (con commit, en stage, sin stage y sin seguimiento). Los tests corren solo para los archivos de test asociados a los archivos modificados, y solo si existen.

¿Necesito RuboCop y Brakeman?

No. Ambos son opcionales; los chequeos de herramientas que no están presentes se omiten. Se soportan tanto RSpec como Minitest.

¿El generador va a sobrescribir mis archivos?

Volver a correrlo es seguro: solo actualiza el bloque marcado en AGENTS.md/CLAUDE.md, agrega los hooks que falten sin tocar tus otros ajustes y conserva un config/agent_harness.yml y un SKILL.md existentes, salvo que pases --force.

¿Qué versiones de Ruby y Rails?

Ruby 3.3, 3.4 y 4.0 con Rails 8.1, probados en CI, más Rails main como job edge al que se le permite fallar. Solo se soportan las versiones que siguen mantenidas oficialmente.

¿Funciona en un monorepo?

Instala el harness en el directorio de la app Rails e inicia Claude Code ahí; Claude Code lee .claude/settings.json del directorio en el que arranca.

¿Qué necesita el servicio de configuración de nuestra parte?

Acceso al repositorio (o una sesión de pairing sobre él) y alguien de tu equipo con quien acordar las convenciones. El alcance, los accesos y cualquier término de confidencialidad se acuerdan por escrito antes de empezar.
