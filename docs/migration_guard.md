# Migration and schema guard

Agents like to hand-write migration files and "fix" `db/schema.rb` directly. Both bypass
Rails' schema workflow: hand-written migrations get wrong timestamps or class names, and a
hand-edited schema drifts from the database. rails_agent_harness stops this in two layers.

## 1. Claude Code: a `PreToolUse` hook (hard block)

`bin/rails g agent_harness:install` adds this hook to `.claude/settings.json`:

```json
{ "matcher": "Edit|Write",
  "hooks": [{ "type": "command", "command": "\"${CLAUDE_PROJECT_DIR}\"/bin/agent-check hook pre-tool-use", "timeout": 10 }] }
```

Before each `Write` or `Edit`, `bin/agent-check hook pre-tool-use` reads the tool call and:

| Tool call | Guard | Result |
|---|---|---|
| `Write`/`Edit` of a schema file: `db/schema.rb`, `db/structure.sql`, `db/*_schema.rb`, `db/*_structure.sql` | `guards.schema` | blocked |
| `Write` of a migration file that doesn't exist yet: `db/migrate/*.rb`, `db/*_migrate/*.rb` | `guards.migrations` | blocked |
| `Edit`/`Write` of an existing (generated) migration | | allowed |
| Anything else, including `Bash` (`bin/rails g migration ...`, `bin/rails db:migrate`) | | allowed |

A blocked call exits with status 2 and the reason on stderr; Claude Code cancels the tool
call and shows the reason to Claude. The hook runs no git commands or subprocesses.

## 2. Every agent: the `migrations` check in `bin/agent-check`

Codex, Cursor and other agents have no hooks, so `bin/agent-check` (which runs the
`migrations` check first) applies a heuristic to the files changed since the merge base:

1. **Filename** (`guards.migrations`): each *added* migration is named
   `YYYYMMDDHHMMSS_snake_name.rb`, and the timestamp is a valid UTC time at most 24 hours in
   the future.
2. **Class name** (`guards.migrations`): the file defines
   `class <SnakeName camelized> < ActiveRecord::Migration[x.y]`. The comparison ignores
   case, so inflection acronyms such as `AddAPIKey` pass.
3. **Schema updated** (`guards.schema`): when a migration is added under `db/migrate`, the
   app's schema file (`db/schema.rb`, or `db/structure.sql` for `schema_format = :sql`) has
   changed too, and `db/schema.rb`'s `define(version: ...)` is at least the newest added
   migration's timestamp.
4. **Schema without migration** (`guards.schema`): a schema file changed and no migration
   file was added or modified.

Each problem is one line, for example:

```
[migrations] FAIL 1 problem
  db/migrate/add_views_to_posts.rb: does not look generated by bin/rails g migration (expected YYYYMMDDHHMMSS_snake_name.rb)
```

## Configuration

```yaml
# config/agent_harness.yml
guards:
  migrations:
    enabled: true   # PreToolUse block on new migration files; rules 1-2
  schema:
    enabled: true   # PreToolUse block on schema files; rules 3-4
```

The two guards are independent. With both disabled, the hook allows everything and the
`migrations` check is skipped.

## Known limits

The heuristic is deliberately simple: false negatives are acceptable, false positives
should be rare and explainable.

- **Without the hook, a hand-written file can pass.** An agent that writes a file with a
  plausible timestamp and the right class name is indistinguishable from the generator's
  output. In Claude Code the `PreToolUse` hook closes this gap.
- **`db:migrate` after pulling base-branch migrations trips rule 4.** Merging the base
  branch and running `bin/rails db:migrate` changes the schema without a migration on this
  branch. Commit that schema change on its own (it then belongs to the merge), or set
  `guards.schema.enabled: false`.
- **The first `db:migrate` after upgrading to Rails 8.1 trips rule 4 too.** Rails 8.1 dumps
  `db/schema.rb` with each table's columns sorted alphabetically, so the first re-dump
  changes the file without a migration. Commit that re-dump on its own.
- **Secondary databases only get rules 1-2.** Rule 3 checks the primary database
  (`db/migrate` against `db/schema.rb`/`db/structure.sql`); migrations in
  `db/<name>_migrate` (multi-database apps, Solid Queue/Cache/Cable) aren't matched to
  their schema files.
- **`db/structure.sql` isn't version-checked.** Rule 3 only requires it to have changed.
- **Non-timestamped migrations fail rule 1.** Apps with
  `config.active_record.timestamped_migrations = false` (`001_create_posts.rb`) should
  disable `guards.migrations`.
- **Files written outside Claude's file tools** (for example `cat > db/schema.rb` through
  `Bash`) aren't blocked by the hook; rule 4 still reports them in `bin/agent-check`.
