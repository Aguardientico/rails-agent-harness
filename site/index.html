Open source · MIT · Rails 8.1

Guard rails for AI coding agents in your Rails app.

rails_agent_harness gives Claude Code, Codex and Cursor the same instructions, checks and guards, so their changes go through RuboCop, Brakeman and your tests, and migrations come from the generator, before the agent says “done”.

Agents are fast. In a Rails app they repeat the same mistakes.

Hand-written migrations

No timestamp, wrong class name, and direct edits to db/schema.rb, so the schema drifts from the database.

Risky Rails code

N+1 queries, unscoped params, string-interpolated SQL and side effects in callbacks.

“Done” without checking

The task is declared finished without running the linter, the security scanner or the tests.

How it works

  1. Install and generate

    Add the gem and run bin/rails g agent_harness:install. The generator detects your stack (Rails version, RSpec or Minitest, database, RuboCop/Standard, Brakeman, schema.rb or structure.sql) and writes the files above. Commit them so every developer and agent gets the same setup.

  2. The agent runs one command

    bin/agent-check checks the files changed since the merge base with your base branch, without booting Rails. Here is the output for a careless change from the recorded demo: 

$ bin/agent-check
agent-check: FAIL (migrations, rubocop, brakeman) - 5 files checked in Xs
[migrations] FAIL 1 problem
  db/migrate/add_published_to_posts.rb: does not look generated by bin/rails g migration (expected YYYYMMDDHHMMSS_snake_name.rb)
[rubocop] FAIL 1 offense
  app/models/post.rb:9:5: C: [Correctable] Style/StringLiterals: Prefer double-quoted strings unless you need single quotes to avoid extra backslashes for escaping.
[brakeman] FAIL 1 warning
  app/controllers/posts_controller.rb:5 [High] SQL Injection: Possible SQL injection
[tests] SKIP disabled in config/agent_harness.yml
Fix the issues above, then run bin/agent-check again.
(exit 1)

# After generating the migration, parameterizing the query and fixing the style offense:
$ bin/agent-check
agent-check: PASS (migrations, rubocop, brakeman, tests skipped: disabled in config/agent_harness.yml) - 5 files checked in Xs

  1. Claude Code is stopped before it slips

    Hooks in .claude/settings.json block a hand-written migration or a schema edit before it happens, lint every edited file, and run the full check before Claude stops. Codex and Cursor read AGENTS.md, which tells them to run bin/agent-check and fix everything it reports.

What you get

AGENTS.md + CLAUDE.md

Commands and conventions for your app's stack, inside BEGIN/END markers. CLAUDE.md imports AGENTS.md. Re-running the generator only refreshes the marked block and keeps your own text.

bin/agent-check

One fast command for the change set: migration and schema rules, RuboCop (or Standard) on changed files, Brakeman, and the tests mapped to the changed files (RSpec or Minitest). Plain-text output, one line when everything passes.

Claude Code hooks

  • PreToolUse: blocks hand-written migrations and schema edits
  • PostToolUse: RuboCop on the edited file, offenses fed back
  • Stop: the full check before Claude finishes

Migration & schema guard

Migrations must come from bin/rails g migration, and the schema only changes through db:migrate. Flags misnamed migrations, a migration without a schema change, and a schema change without a migration.

rails-review skill

Ask Claude to “review my changes” or run /rails-review: N+1 queries, missing indexes, strong parameters, callbacks, transactions, security and tests. The same checklist lives in AGENTS.md for other agents.

Configurable, safe to re-run

config/agent_harness.yml sets the base branch, output limits, each check's command and the guards. Tools you don't use are skipped. Existing hooks and settings are kept.

Compatibility: Ruby 3.3, 3.4 and 4.0 · Rails 8.1 (tested in CI), Rails main as an edge job · RSpec or Minitest · RuboCop/Standard and Brakeman optional. Full documentation in the README.

FAQ

Is the gem free?

Yes. The core gem is, and will stay, MIT licensed. Additional paid packs may come later.

Which agents does it support?

Claude Code reads CLAUDE.md (which imports AGENTS.md) and gets hooks and the rails-review skill. Codex and Cursor read AGENTS.md. The generator only installs hooks for Claude Code; for the others, the migrations check in bin/agent-check catches hand-written migrations after the fact.

Does bin/agent-check boot Rails or run the whole suite?

No. It never boots Rails, and it checks the files changed since the merge base with your base branch (committed, staged, unstaged and untracked). Tests run only for test files mapped to the changed files, and only if they exist.

Do I need RuboCop and Brakeman?

No. Both are optional; checks for tools that aren't present are skipped. RSpec and Minitest are both supported.

Will the generator overwrite my files?

Re-running it is safe: it only refreshes the marked block in AGENTS.md/CLAUDE.md, adds missing hooks without touching your other settings, and keeps an existing config/agent_harness.yml and SKILL.md unless you pass --force.

Which Ruby and Rails versions?

Ruby 3.3, 3.4 and 4.0 with Rails 8.1, tested in CI, plus Rails main as an allowed-to-fail edge job. Only versions still maintained upstream are supported.

Does it work in a monorepo?

Install the harness in the Rails app's directory and start Claude Code there; Claude Code reads .claude/settings.json from the directory it starts in.

What does the setup service need from us?

Access to the repository (or a pairing session on it) and someone on your team to agree conventions with. Scope, access and any confidentiality terms are agreed in writing before we start.
