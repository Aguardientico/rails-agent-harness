# rails_agent_harness

Make AI coding agents (Claude Code, Codex, Cursor) safe and productive in Rails apps.

## Why

Coding agents are fast, but in a Rails app they make the same mistakes over and over:

- they **hand-write migrations** (no timestamp, wrong class name) and **edit `db/schema.rb`** directly, so the schema drifts from the database;
- they add **N+1 queries**, **unscoped `params`**, string-interpolated SQL and side effects in callbacks;
- they declare a task "done" without running the linter, the security scanner or the tests.

rails_agent_harness gives every agent the same guard rails:

- an **`AGENTS.md`** (and a `CLAUDE.md` that imports it) with commands and conventions for *your* app's stack;
- **`bin/agent-check`**, one fast command that checks the change set: migrations and schema, RuboCop on changed files, Brakeman, and the tests mapped to the changed files;
- **Claude Code hooks** that block hand-written migrations and schema edits before they happen, lint every edited file, and run the full check before Claude stops;
- a **`rails-review` skill** (and the same checklist in `AGENTS.md`) for reviewing changes for N+1 queries, missing indexes, strong parameters, callbacks, transactions and security.

## Install

```bash
bundle add rails_agent_harness --group development
bin/rails g agent_harness:install
```

The generator detects your stack (Rails version, RSpec or Minitest, database, RuboCop/Standard, Brakeman, `schema.rb` or `structure.sql`) and writes:

```
AGENTS.md                              agent instructions for this app (inside BEGIN/END markers)
CLAUDE.md                              imports AGENTS.md for Claude Code (@AGENTS.md)
config/agent_harness.yml               settings (kept on re-runs unless --force)
bin/agent-check                        the checker
.claude/settings.json                  Claude Code hooks (merged into an existing file)
.claude/skills/rails-review/SKILL.md   the rails-review skill
```

Commit them, so every developer and agent gets the same setup. Re-running the generator is safe: it only refreshes the marked block in `AGENTS.md`/`CLAUDE.md`, keeps your own text around it, adds missing hooks without touching your other settings, and keeps an existing `config/agent_harness.yml` and `SKILL.md`.

Options:

| Option | Effect |
|---|---|
| `--force` | Overwrite `config/agent_harness.yml` and `.claude/skills/rails-review/SKILL.md` |
| `--skip-claude-hooks` | Don't add hooks to `.claude/settings.json` |
| `--skip-skills` | Don't write `.claude/skills/` (the review section stays in `AGENTS.md`) |

## How it works with each agent

**Claude Code** reads `CLAUDE.md`, which imports `AGENTS.md`, and runs these hooks from `.claude/settings.json`:

| Hook | Runs | Effect |
|---|---|---|
| `PreToolUse` (`Edit\|Write`) | `bin/agent-check hook pre-tool-use` | Blocks hand-written migration files and edits to the schema (exit 2, reason shown to Claude) |
| `PostToolUse` (`Edit\|Write`) | `bin/agent-check hook post-tool-use` | RuboCop on the edited file; offenses are fed back to Claude |
| `Stop` | `bin/agent-check hook stop` | The full check before Claude finishes; failures send it back to work (once per stop) |

Ask Claude to "review my changes" or run `/rails-review` to use the review skill.

**Codex and Cursor** read `AGENTS.md`, which tells them to run `bin/agent-check` before saying a task is done and to fix everything it reports, and contains the same review checklist. They have no hooks, so the migrations check in `bin/agent-check` catches hand-written migrations after the fact.

## `bin/agent-check`

```
Usage: bin/agent-check [options]
       bin/agent-check hook pre-tool-use|post-tool-use|stop

    --only CHECKS     Run only these checks (comma-separated: migrations, rubocop, brakeman, tests)
    --files FILES     Check these files instead of the changed files
    --base BRANCH     Branch to diff against (default: base_branch in config)
    --verbose         Don't truncate check output
    --version         Print the version
    -h, --help        Print this help
```

It checks the files changed since the merge base with `base_branch` (committed, staged, unstaged and untracked) and never boots Rails:

| Check | What it does |
|---|---|
| `migrations` | Migration/schema rules (see [Migration guard](#migration-guard)) |
| `rubocop` | RuboCop (or Standard) on the changed Ruby files; uses `bin/rubocop` when present |
| `brakeman` | Brakeman when something under `app/`, `config/`, `lib/` or `Gemfile.lock` changed; fails on High/Medium confidence warnings, and when it couldn't parse a changed file |
| `tests` | The tests mapped to the changed files (`bundle exec rspec`/`bin/rspec`, or `bin/rails test`) |

Exit status: `0` when nothing failed, `1` when a check failed. As a hook, it exits `2` only for a check failure (or a blocked tool call), `0` for a pass, a skip or bad input, and `1` for an internal error.

Output is plain text, one line when everything passes; each check's details are capped at `max_output_lines` (`--verbose` shows everything).

Tests mapped to changed files:

| Changed file | RSpec | Minitest |
|---|---|---|
| `spec/**/*_spec.rb` / `test/**/*_test.rb` | itself | itself |
| `app/<dir>/<path>.rb` | `spec/<dir>/<path>_spec.rb` | `test/<dir>/<path>_test.rb` |
| `app/controllers/<path>_controller.rb` | also `spec/requests/<path>_spec.rb` | also `test/integration/<path>_test.rb` |
| `app/views/<resource>/**` | `spec/requests/<resource>_spec.rb` | `test/controllers/<resource>_controller_test.rb` |
| `lib/<path>.rb` | `spec/lib/<path>_spec.rb` | `test/lib/<path>_test.rb` |
| anything else (migrations, schema, routes, config) | none | none |

Only test files that exist are run.

## Configuration

`config/agent_harness.yml` (generated with comments; unknown keys are warned about and ignored, and values of the wrong type are an error):

```yaml
# Branch used to compute "changed files" (the merge base with this branch).
base_branch: main

# Maximum number of output lines each check prints in bin/agent-check.
max_output_lines: 40

checks:
  rubocop:
    enabled: true     # false: skip RuboCop
    command: null     # null: bin/rubocop, else standardrb (Standard apps), else bundle exec rubocop
  brakeman:
    enabled: true     # false: skip Brakeman
    command: null     # null: bin/brakeman, else bundle exec brakeman
  tests:
    enabled: true     # false: skip mapped tests
    command: null     # null: bin/rspec or bundle exec rspec (RSpec), bin/rails test (Minitest)

guards:
  migrations:
    enabled: true     # block new hand-written migration files; migration filename and class name rules
  schema:
    enabled: true     # block schema edits; "migration without schema change" and "schema change without migration" rules
```

| Key | Default | Effect |
|---|---|---|
| `base_branch` | `main` | Base for "changed files"; falls back to `origin/<base_branch>`, then `HEAD` |
| `max_output_lines` | `40` | Lines of details per check before truncation (positive integer) |
| `checks.rubocop.enabled` | `true` | Run the RuboCop check (the generator sets `false` when RuboCop isn't detected) |
| `checks.rubocop.command` | `null` | Command to run instead of the detected one; changed files are appended |
| `checks.brakeman.enabled` | `true` | Run the Brakeman check (`false` when Brakeman isn't detected) |
| `checks.brakeman.command` | `null` | Command to run instead of the detected one |
| `checks.tests.enabled` | `true` | Run mapped tests (`false` when no test framework is detected) |
| `checks.tests.command` | `null` | Command to run instead of the detected one; mapped test files are appended |
| `guards.migrations.enabled` | `true` | Migration rules and the hook's block on new migration files |
| `guards.schema.enabled` | `true` | Schema rules and the hook's block on schema edits |

## Migration guard

Migrations must come from `bin/rails g migration` (or `g model`), and `db/schema.rb`/`db/structure.sql` must only change through `bin/rails db:migrate`:

- **Claude Code**: the `PreToolUse` hook blocks `Write`/`Edit` of a schema file and `Write` of a new migration file. Editing a generated migration and running `bin/rails g migration` or `db:migrate` stay allowed.
- **Every agent**: the `migrations` check in `bin/agent-check` reports added migrations whose filename isn't `YYYYMMDDHHMMSS_snake_name.rb` or whose class doesn't match it, a migration added without a schema change (or with an older schema version), and a schema change without a migration.

The heuristic and its known limits are documented in [`docs/migration_guard.md`](docs/migration_guard.md).

## Compatibility

- **Ruby** 3.3, 3.4 and 4.0, and **Rails** 8.1 (tested in CI), plus Rails `main` (tested as an allowed-to-fail edge job). Only versions still maintained upstream are supported; old ones are dropped when they reach end of life.
- RSpec or Minitest. RuboCop/Standard and Brakeman are optional: checks for tools that aren't present are skipped.
- Known limitations: in a monorepo, install the harness in the Rails app's directory and start Claude Code there (Claude Code reads `.claude/settings.json` from the directory it starts in); and with Claude Code worktrees, the post-edit RuboCop hook skips files edited inside a worktree.
